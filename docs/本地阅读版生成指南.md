# 本地阅读版生成指南

两份交付文件固定放在工程内：

- `output/html/Better-Life.html`：独立离线书库，适合手机和电脑浏览器。
- `output/pdf/Better-Life.pdf`：完整文字版电子书，内嵌字体，带可点击目录与分层书签。
- `output/版本信息.json`：正文来源提交、日期、数量、成品大小和 SHA-256，随成品更新。

HTML 包含所有正文、9 篇长文、7 篇原创专题与 SVG 插图，不依赖网络字体、外部脚本或服务器。外部文献链接需要联网。手机请用支持 JavaScript 的浏览器打开 HTML；聊天软件的文件预览可能不运行脚本，PDF 则可直接在系统阅读器中查看。收藏与进度保存在当前浏览器，不能跨设备自动同步。

## 首次准备

需要 Node.js 20+、Python 3.10+、curl。所有新增依赖只安装在项目目录，不修改全局配置。

```sh
npm ci
python3 -m venv .cache/publication/venv
.cache/publication/venv/bin/python -m pip install -r tools/publication/requirements.txt
```

Windows 的 Python 可执行文件在 `.cache/publication/venv/Scripts/python.exe`。如果已有包含这些依赖的环境，可设置 `PUBLICATION_PYTHON` 指向该解释器。

## 每次同步后的生成

```sh
npm run editions
```

命令依次执行：

1. 重建网站配套的离线版本，写入 `dist/HowToLiveBetter.html`。
2. 从 `book/*.md`、`content/upstream-sync.json` 的长文清单、`content/human-system.json` 读取同一份内容，生成独立 HTML 和供排版使用的中间数据。
3. 首次下载 Noto Sans SC 开源字体，核对固定 SHA-256，再生成常规和半粗字重；以后使用本地缓存。
4. 使用 ReportLab 直接排出 PDF。它是文字、路径、链接和内嵌字体组成的文档，不经过截图或图片拼接。
5. 为两份成品写入版本和校验清单。

首次生成需要联网取得字体；缓存和依赖齐全后可断网构建。字体使用 SIL Open Font License，许可保存在 `tools/publication/OFL-NotoSansSC.txt`；下载地址和固定校验值保存在 `font-source.json`。字体内容变化会使构建明确失败，核对新来源后再更新校验值。

## 设计修改位置

| 文件 | 作用 |
|---|---|
| `tools/publication/reader.html` | 独立 HTML 的版式、交互与响应式样式 |
| `tools/publication/build.cjs` | 统一解析正文、长文和专题，不重新改写原文 |
| `tools/publication/pdf.py` | PDF 封面、扉页、目录、文字样式、页眉页码和链接 |
| `tools/publication/fonts.py` | 字体取得、校验和字重实例化 |
| `tools/publication/run.mjs` | 单命令构建入口与成品清单 |

PDF 页面为 190 × 260 mm，单栏阅读。正文 10.4 pt、行距 17.5 pt；条目标题、白话摘要、成本收益、备注和来源采用不同层级。封面采用森林绿和浅柠檬色矢量图形，章节留白与纸白正文统一。目录和 PDF 书签提供直接跳转，675 条建议均有子书签。

原 `node tools/pdf/build.mjs` 也转到新生成器；提供输出路径参数时，会额外复制 PDF 到该路径。旧 `template.typ` 仅保留作历史参考，不再参与成品构建。

## 验收

```sh
npm run test:editions
.cache/publication/venv/bin/python tools/publication/verify.py
```

浏览器检查需要 Chrome；脚本用 Playwright 驱动本机 Chrome。检查 320、390、768、1440 宽度下的离线打开、目录、翻页、返回、搜索、收藏、字号、深浅色及零网络请求。PDF 检查全部页面可提取文字、正文标题与段落完整、字体嵌入、书签/目录链接有效、文字不超出页面边界；抽取封面、目录、扉页、正文、长文表格及专题页面渲染检查。

`verify.py` 的中间图像与报告放在 `.cache/publication/proof/`，不作为交付文件提交。不要只看测试通过就交付：每次模板变化后，还要打开渲染图确认留白、断页、长标题、表格和小字来源都清楚。

建议连同更新后的 Markdown、模板、`package-lock.json`、许可证、两份成品及版本清单一起提交。不要手工修改成品 HTML 或 PDF，所有调整回到源模板后重新生成。
